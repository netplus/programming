# C++ 中高级学习与考试验收流程

## 总目标

目标不是刷题，也不是记忆“看到某种代码就选某个答案”。

整个学习过程以 **建立 C++ 语言设计哲学、对象模型、规则逻辑和可推导的心智模型** 为第一目标。选择题只是验收工具，用来检查是否真正理解规则以及能否在组合场景中正确推导。

当前默认语义基线为 **C++17**，除非专题或题目明确指定其它标准版本。

## 学习原则

每个专题优先按下面的层次展开：

1. **设计问题**：这项语言机制要解决什么工程问题；
2. **设计哲学**：C++ 为什么选择这种机制，而不是其它更简单的方案；
3. **对象/执行模型**：编译期和运行期到底发生什么；
4. **语言规则**：标准规则之间如何相互约束；
5. **工程意义**：真实代码为什么要这样设计；
6. **边界与反例**：哪些相似场景实际上遵循不同规则；
7. **选择题验收**：最后再用少量题目验证是否能够独立推导。

如果一道题答错，优先寻找缺失的底层概念或错误的心智模型，而不是记录题目答案。

## 当前学习主线

### 阶段 1：对象生命周期与特殊成员函数

重点建立统一模型：

- constructor / destructor；
- copy construction / copy assignment；
- move construction / move assignment；
- `= default` / `= delete`；
- implicitly-declared / user-declared / user-provided / deleted；
- RAII；
- Rule of Three / Five / Zero；
- virtual destructor；
- C++17 copy elision 与 NRVO。

专题文档：`notes/object-lifetime-and-special-members.md`。

在该专题没有形成稳定理解前，不继续提高刷题频率。

### 后续主线

完成对象生命周期专题后，再逐步进入：

- overload / override / name hiding 与函数决议；
- 继承、虚函数、动态绑定与对象模型；
- 引用、指针、值类别与 forwarding；
- 模板参数推导；
- STL 容器、迭代器和算法语义；
- 智能指针和资源所有权模型；
- 异常安全与现代 C++ 设计原则。

## 题目的定位

题目只承担三种职责：

1. 检查是否能从规则推导结果；
2. 暴露两个相近概念之间是否仍有混淆；
3. 验证多个语言机制组合时，心智模型是否仍然稳定。

因此不追求题量，也不以连续刷题作为学习节奏。

典型流程为：

```text
专题学习
  ↓
自己复述设计逻辑
  ↓
少量概念检查
  ↓
少量选择题验收
  ↓
针对暴露出的概念缺口继续专题学习
```

## 复盘原则

遇到任何 C++ 题目，优先问：

1. 这段代码表达的类型语义是什么；
2. 哪些规则发生在编译期，哪些发生在运行期；
3. 对象是否已经构造完成、是否仍处于有效生命周期；
4. 静态类型和动态类型分别是什么；
5. 编译器隐式声明/默认生成了哪些函数；
6. 有没有函数只是 `deleted`，而不是“不存在”；
7. base/member 的能力如何传播到外层类型；
8. 最后才进行 overload resolution、virtual dispatch 或输出判断。

最终目标是做到：即使题目形式从未见过，也能从设计模型和语言规则一步步推出答案。
